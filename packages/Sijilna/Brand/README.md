# Sijilna Brand

The Sijilna branding override layer for this fork of Krayin CRM. It changes
user-facing vendor marks **without editing a single core file** under
`packages/Webkul/**`; every surface here is an override or a configuration
value, so upstream `2.2` keeps merging cleanly.

## Layout decision — why the provider is not in this package

The brand *resources* live here, but the service provider is
`app/Providers/BrandingServiceProvider.php`.

- `App\` is already autoloaded, so a provider in `app/Providers` needs **no
  composer manifest change** — no new PSR-4 entry, no `composer dump-autoload`,
  no `composer update`, no lock churn and no network. `composer.json` is
  therefore untouched by this package.
- The package is not a composer package on purpose. Adding `Sijilna\Brand\` to
  `autoload.psr-4` would dirty `composer.json`/`composer.lock` on every future
  merge for no functional gain.
- Because of that, this package's classes are **not autoloaded**. Two files are
  loaded explicitly, both from `app/Providers/BrandingServiceProvider.php`:
  - `src/Brand.php` (the brand constants, required at boot)
  - `src/Console/Commands/BrandCommand.php` (required in console only)

  If this package ever becomes a composer package, both `require_once` calls and
  the `loadBrandConstants()`/`register()` plumbing can be deleted.

The provider is appended **last** in `bootstrap/providers.php` so its `boot()`
runs after every Webkul provider and its overrides win. That one appended line
is the package's entire merge cost in upstream-owned files.

## What it overrides

| Surface | Mechanism |
| --- | --- |
| Footer credit | `config(['settings.footer.label' => …])` — `SystemConfig::getDefaultConfig()` drops the leading code segment, so this config key is the rendered default. No core edit, no database row needed. |
| View namespaces | `prependNamespace('admin' \| 'installer' \| 'web_form', …)` puts `resources/views/<namespace>` first. Anything not shipped here falls through to core. |
| Vendor logo route | Replaces the `image_cache` route (same URI, same `where`, same name) so `ImageCacheController` — which fetched `https://updates.krayincrm.com/krayin.png` over the network — is never reached. The response is served from `resources/assets/`. |
| Branding values | `php artisan sijilna:brand` upserts the `general.settings.footer.label` row through `CoreConfigRepository`, the same path the admin Settings screen uses. |

`resources/views/vendor/<hint>` is deliberately **not** used: Laravel would probe
it, but `resources/views/.gitignore` ignores everything there, so an override
placed in it could never be committed.

`resources/views/{admin,installer,web_form}/` are currently empty apart from a
`.gitkeep` that documents the extension point; no blade file is shipped yet, so
every view still falls through to core.

## Assets

`resources/assets/` holds copies of the approved marks from `brand/` (the
source of truth): `sijilna-mark.svg`, `sijilna-mark-favicon.svg`,
`sijilna-wordmark.svg`, `sijilna-wordmark-ar.svg`.

Built/admin bundle artwork (`public/admin/build/**`,
`public/installer/build/**`) is **not** replaced here — those files are build
output and are regenerated by `npm run build` from
`packages/Webkul/*/src/Resources/assets/images/`. Swapping the admin header,
mail and installer logos therefore needs a view override plus a rebuilt bundle,
not this package alone.
